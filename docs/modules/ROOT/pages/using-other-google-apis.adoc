= Google Cloud Services - Using other Google APIs

include::./includes/attributes.adoc[]

The Google Cloud Services extension pack provides dedicated extensions for many Google Cloud services.
If you need a Google API that does not have a dedicated extension, you can still reuse the credentials that the extension injects as CDI beans.
This page shows how to inject those credentials and pass them to the official Google client libraries.

[[credentials-and-credentials-provider]]
== `Credentials` and `CredentialsProvider`

The extension produces two credential beans:

* `com.google.auth.Credentials` (`@Default`) is the credentials used by the Google Cloud client libraries.
Inject it when you build an HTTP-based client with `google-api-client`.
* `com.google.api.gax.core.CredentialsProvider` (`@Default`) is a `FixedCredentialsProvider` wrapping the `Credentials` bean.
Inject it when you build a gRPC-based client with the `*Settings` classes from `google-api-gax`.

The credentials are resolved using the usual xref:index.adoc#authenticating[authentication flow].
Both beans are singletons; create scoped copies per client/API instead of mutating the injected instance.

[[rest-based-apis]]
== Calling a REST-based Google API

REST-based Google APIs, such as the YouTube Data API, are usually called with a client generated by https://github.com/googleapis/google-api-java-client[`google-api-client`].
Those clients take an `HttpRequestFactory`, which can be built with an `HttpCredentialsAdapter` that adds the OAuth 2 access token to every request.

Add the client dependency for the API you want to use.
For example, for YouTube:

[source,xml]
----
<dependency>
  <groupId>com.google.apis</groupId>
  <artifactId>google-api-services-youtube</artifactId>
  <version>${google-api-services-youtube.version}</version>
</dependency>
----

The version of `google-api-services-*` artifacts is not managed by this project's BOM, so choose the version that matches the API and the `google-api-client` version in use.

Then inject `Credentials`, scope it to the API, and build the client:

[source,java]
----
import java.util.List;

import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;

import org.eclipse.microprofile.config.inject.ConfigProperty;

import com.google.api.client.googleapis.javanet.GoogleNetHttpTransport;
import com.google.api.client.http.HttpRequestFactory;
import com.google.api.client.http.javanet.NetHttpTransport;
import com.google.api.client.json.gson.GsonFactory;
import com.google.api.services.youtube.YouTube;
import com.google.auth.Credentials;
import com.google.auth.http.HttpCredentialsAdapter;
import com.google.auth.oauth2.GoogleCredentials;

@Path("/youtube")
public class YouTubeResource {

    private static final String YOUTUBE_READONLY_SCOPE = "https://www.googleapis.com/auth/youtube.readonly";

    @Inject
    Credentials credentials;

    @ConfigProperty(name = "quarkus.google.cloud.project-id")
    String projectId;

    @GET
    public String search() throws Exception {
        NetHttpTransport transport = GoogleNetHttpTransport.newTrustedTransport();

        HttpRequestFactory requestFactory;
        if (credentials instanceof GoogleCredentials googleCredentials) {
            requestFactory = transport.createRequestFactory(
                    new HttpCredentialsAdapter(googleCredentials.createScoped(YOUTUBE_READONLY_SCOPE)));
        } else {
            // NoCredentials, used with emulators and tests, cannot be adapted by HttpCredentialsAdapter
            requestFactory = transport.createRequestFactory();
        }

        YouTube youtube = new YouTube.Builder(transport, GsonFactory.getDefaultInstance(), requestFactory)
                .setApplicationName("my-quarkus-app")
                .build();

        // Some Google APIs use this header to attribute quota/billing to a project
        YouTube.Search.List request = youtube.search()
                .list(List.of("snippet"))
                .setQ("quarkus");
        request.getRequestHeaders().set("X-Goog-User-Project", projectId);
        return request.execute().toString();
    }
}
----

TIP: `GoogleCredentials#createScoped(...)` returns a new credentials instance with the requested scopes.
Keep the injected `Credentials` bean unchanged and create a scoped copy for each API that needs different scopes.

[[grpc-based-apis]]
== Calling a gRPC-based Google API

gRPC-based Google APIs are generated from https://github.com/googleapis/gax-java[`gax-java`] and are configured with a `*Settings` builder.
Pass the injected `CredentialsProvider` to `setCredentialsProvider(...)`:

[source,java]
----
import jakarta.enterprise.context.ApplicationScoped;
import jakarta.inject.Inject;

import com.google.api.gax.core.CredentialsProvider;
import com.google.cloud.someapi.v1.SomeApiClient;
import com.google.cloud.someapi.v1.SomeApiSettings;

@ApplicationScoped
public class SomeApiService {

    @Inject
    CredentialsProvider credentialsProvider;

    public void call() throws Exception {
        SomeApiSettings settings = SomeApiSettings.newBuilder()
                .setCredentialsProvider(credentialsProvider)
                .build();

        try (SomeApiClient client = SomeApiClient.create(settings)) {
            // Call the API
        }
    }
}
----

The xref:bigtable.adoc[Bigtable] and xref:pubsub.adoc[PubSub] guides show this pattern with real clients.

[[emulators-and-tests]]
== Emulators and tests

When the application runs against an emulator or in a test without real Google credentials, the extension can inject `com.google.cloud.NoCredentials`.

* `NoCredentials` is not compatible with `HttpCredentialsAdapter`.
Check the credential type before wrapping it, as the REST example above does, or create the `HttpRequestFactory` without an adapter.
* For gRPC clients, use `com.google.api.gax.core.NoCredentialsProvider` (for example `NoCredentialsProvider.create()`), because `FixedCredentialsProvider` cannot wrap `NoCredentials` either.
* Some client libraries also require an emulator host or a custom endpoint.
See the service-specific guides and xref:index.adoc#emulators[the emulators section of the main page].

[[scopes-and-access-tokens]]
== Scopes and access tokens

* Request only the scopes the target API needs.
The extension scopes the default credentials to `https://www.googleapis.com/auth/cloud-platform`; create a scoped copy with the API-specific scopes when necessary.
* When `quarkus.google.cloud.access-token-enabled` is `true`, the extension can create `Credentials` from the bearer token of the current `SecurityIdentity`.
This is useful for calling Google APIs on behalf of the signed-in user.
The extension does not add scopes to that token, so it must already be valid for the target API.
* Access tokens expire.
The Google client libraries refresh `GoogleCredentials` automatically when possible, but tokens created from a `SecurityIdentity` bearer token cannot be refreshed by the extension.
